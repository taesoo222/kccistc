# Stopwatch + Watch (STM32)

## Overview

A two-mode 4-digit 7-segment (FND) project on an **STM32F411RE** (100 MHz from
an 8 MHz HSE), written in C with the STM32 HAL.

- **Stopwatch mode**: start/stop and clear. Counts up by 1 every 100 ms
  (0.1 s per count) and wraps from 9999 to 0.
- **Watch mode**: shows `MM.SS`. The middle decimal point blinks every 0.5 s.

A mode button switches between the two. Both counters keep running in the
background while the other mode is shown.

TIM3 generates a 1 ms interrupt that refreshes the FND and drives software
timers, so the main loop does not need a delay to keep the display stable.

## Project Structure

```
MINI_STM32_Stopwatch_watch/
├── HW_StopWatch_Watch.ioc          # STM32CubeMX configuration (MCU, clock, pins, TIM3)
└── Core/Src/
    ├── main.c                      # CubeMX init, then calls ap_main()
    ├── ap/
    │   ├── ap_main.c/.h            # Mode FSM (STOPWATCH <-> WATCH), 100 ms tick
    │   ├── StopWatch/StopWatch.c/.h  # STOP / RUN / CLEAR FSM
    │   └── Watch/Watch.c/.h        # MM.SS clock
    └── driver/
        ├── button/button.c/.h      # Edge detection + 5 ms debounce
        ├── led/led.c/.h            # LED on/off/toggle
        ├── fnd/fnd.c/.h            # 4-digit multiplexing, segment patterns, DP
        └── timer/timer.c/.h        # TIM3 1 ms ISR, callback slots (max 4)
```

Only hand-written code and the `.ioc` file are kept. Everything else is
generated by STM32CubeIDE and is not tracked: HAL/CMSIS drivers, startup
file, `system_stm32f4xx.c`, `stm32f4xx_it.c`, `stm32f4xx_hal_msp.c`,
`syscalls.c`, `sysmem.c`, headers in `Core/Inc/`, linker scripts, IDE
settings, and the `Debug/` build output.

## Architecture

### Layers

| Layer | Files | Role |
|---|---|---|
| Application | `ap/` | Mode switching and the per-mode FSMs |
| Driver | `driver/` | Hardware access (GPIO, TIM3) |
| CubeMX | `main.c` | Clock / GPIO / TIM3 init, then `ap_main()` |

### Timing

- **TIM3**: 100 MHz timer clock (APB1 50 MHz × 2) / PSC 100 / ARR 1000 = **1 kHz (1 ms)**.
- On every TIM3 interrupt `HAL_TIM_PeriodElapsedCallback()`:
  1. calls `fnd_show_number()` — one digit per call, so all four digits
     refresh every 4 ms (~250 Hz);
  2. advances every registered timer slot and runs its callback when its
     period is reached.
- `ap_main()` registers `ap_tick_100ms()` with a 100 ms period. It calls both
  `StopWatch_tick_100ms()` and `Watch_tick_100ms()`.

### Mode FSM (`ap_main.c`)

| Mode | Mode button (PC0) | Main loop runs |
|---|---|---|
| `MODE_STOPWATCH` | → `MODE_WATCH` | `StopWatch_task()` |
| `MODE_WATCH` | → `MODE_STOPWATCH` | `Watch_task()` |

On a switch, the old mode's `_exit()` and the new mode's `_enter()` run.
These update the mode LEDs and clear the DP.

### Stopwatch FSM (`StopWatch.c`)

| State | Run/Stop (PC1) | Clear (PC3) | Action |
|---|---|---|---|
| `STOP` | press → `RUN` | release → `CLEAR` | Hold the current value, Stop LED on |
| `RUN` | press → `STOP` | — | +1 every 100 ms (in the ISR), Run LED on |
| `CLEAR` | — | — | Reset to 0, then → `STOP` |

### Watch (`Watch.c`)

- Counts 100 ms ticks and wraps after 24 h (864000 ticks).
- Shows `min * 100 + sec`. The DP on digit 2 is on for 0.5 s, then off for 0.5 s.
- Starts at 00:00 on reset. There is no time-setting input.

### Buttons

Active-low. `button_getState()` returns `ACT_PUSH` on a 1 → 0 edge and
`ACT_RELEASE` on a 0 → 1 edge, then waits 5 ms (`HAL_Delay(5)`) as a debounce.

## Pin Map

| Function | Pin | Level |
|---|---|---|
| Mode button | PC0 | Input, low = pressed |
| Stopwatch Run/Stop button | PC1 | Input, low = pressed |
| Stopwatch Clear button | PC3 | Input, low = pressed |
| LED: Stopwatch Stop | PB13 | Output, high = on |
| LED: Stopwatch Run | PC4 | Output, high = on |
| LED: Stopwatch mode | PB14 | Output, high = on |
| LED: Watch mode | PB15 | Output, high = on |
| FND digit 1–4 select | PA5, PB6, PC7, PA10 | Output, low = selected |
| FND segments A–G, DP | PA6, PA9, PB5, PB10, PA8, PA7, PB3, PB4 | Output, high = on |

Digit 1 is the thousands digit; digit 4 is the ones digit.

## Known Issues

- Only the active mode polls its buttons. A button held across a mode switch
  (or Clear held while `RUN` → `STOP`) can fire one stale edge event.
- Run/Stop acts on press, Clear acts on release.
- `timer_reg()` does not check `TIMER_MAX` (4).

## How to Build

1. In STM32CubeIDE, create a project from `HW_StopWatch_Watch.ioc`
   (*File → New → STM32 Project from an Existing STM32CubeMX Configuration File*).
2. Run *Project → Generate Code*.
3. Replace the generated `Core/Src/main.c` with the one here, and copy
   `Core/Src/ap/` and `Core/Src/driver/` into the project.
4. Build and flash.
